Помогите настроить единый постоянный редирект для сайта cook-look.ru.

Нужно перенаправлять за один HTTP 301:
http://cook-look.ru/ПУТЬ?ПАРАМЕТРЫ
http://www.cook-look.ru/ПУТЬ?ПАРАМЕТРЫ
https://www.cook-look.ru/ПУТЬ?ПАРАМЕТРЫ
на https://cook-look.ru/ПУТЬ?ПАРАМЕТРЫ.

Текущая конфигурация: режим PHP с Apache, SSL/HSTS и
«Перенаправлять HTTP-запросы в HTTPS» включены. Панельный «Редирект
домена» отключён. В начало корневого .htaccess добавлен блок
«BEGIN CookLook www redirect», который переводит www на HTTPS без www.

После этой правки HTTPS с www на страницах уже делает один 301
сразу на HTTPS без www; прежний возврат на HTTP устранён.
Но запрос HTTP с www всё ещё проходит два редиректа:
http://www.cook-look.ru/
-> 301 https://www.cook-look.ru:443/
-> 301 https://cook-look.ru/
-> 200.

Кроме того, этот статический файл на www возвращает 200 без редиректа:
https://www.cook-look.ru/wp-content/themes/cooklook/static/css/style.min.css?ver=1792203035

HTTP без www перенаправляется на https://cook-look.ru:443/ за один 301.
Явный стандартный порт не ломает сайт, но просим убрать его из Location.

Пожалуйста, настройте единое правило на внешнем веб-сервере (ответы
содержат Server: nginx), чтобы все три варианта адреса, включая CSS
и другие статические файлы, переходили сразу на HTTPS без www.
Сохраните путь и query string без изменений. Основной адрес
https://cook-look.ru/ не должен перенаправляться; отсутствующие страницы
должны оставаться 404. Учитывайте уже добавленный блок в .htaccess,
чтобы не создать конфликт или цикл.

SSL, действующий сертификат для обоих имён, HSTS и автоматическое
продление сертификата нужно сохранить. Настройка должна применяться
к страницам и статическим файлам и сохраняться при изменениях в панели.
