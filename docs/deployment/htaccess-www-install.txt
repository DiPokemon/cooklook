CookLook: перенос редиректа www в Apache

Область применения
Файл htaccess-www-snippet.txt содержит ДОПОЛНЕНИЕ к существующему .htaccess.
Он не заменяет весь файл и не устанавливается через ZIP темы.
Правило направляет www.cook-look.ru на https://cook-look.ru с кодом 301,
сохраняя исходный путь и параметры запроса.
Это работает только для запросов, которые доходят до Apache.

Порядок установки
1. В файловом менеджере хостинга откройте корень сайта cook-look.ru:
   каталог с index.php, wp-admin, wp-content и загруженным robots.txt.
   При необходимости включите отображение скрытых файлов.
2. Скачайте текущий .htaccess на компьютер как резервную копию.
3. Вставьте содержимое htaccess-www-snippet.txt в самое начало .htaccess,
   перед правилами кеширования и перед строкой # BEGIN WordPress.
   Существующее содержимое сохраните. Сохраните файл без BOM.
4. В панели сайта отключите только «Редирект домена»
   («С www.cook-look.ru на cook-look.ru»).
   Сохраните www.cook-look.ru среди имён/алиасов сайта.
   SSL, сертификат для обоих имён, HSTS и
   «Перенаправлять HTTP-запросы в HTTPS» оставьте включёнными.
5. Сохраните настройки и очистите кеш сайта/CDN.
   Затем требуется повторная проверка HTTP-ответов без браузерного кеша.

Ограничение
На рабочем сайте внешние ответы содержат Server: nginx. В типичной схеме
Nginx + Apache запрос сначала обрабатывает Nginx; часть статических файлов
он отдаёт напрямую. Такие запросы могут не дойти до .htaccess.
При сохранённом принудительном HTTPS запрос http://www.cook-look.ru/
может по-прежнему пройти два редиректа: сначала на HTTPS с www,
затем на HTTPS без www. Явный :443 в первом Location это правило не уберёт.
Поэтому этот вариант сам по себе не закрывает требование одного 301
для всех трёх неосновных вариантов адреса и всех ресурсов.

Для полного решения примените перенаправление на уровне внешнего Nginx.
Готовое описание для поддержки: hosting-redirect-request.txt.
Оно подготовлено локально; сообщение в поддержку не отправлено.

Проверено локально
17.10.2026, изолированный Apache 2.4.54, 18 из 18 сценариев:
www, регистр имени и порт; главная, вложенный путь, статический файл,
пагинация, параметры, повторяющиеся параметры и пустые значения;
кодированная кириллица, пробел, %, #, ? и & в пути;
отсутствие редиректа основного и локального хоста, сохранение 404.
Проверка не подтверждает применение правил на рабочем хостинге.

Проверка после установки на хостинге
17.10.2026, 12:50–12:51 МСК: владелец установил блок и отключил
панельный «Редирект домена». HTTPS с www на проверенных страницах
перенаправляется сразу на основной HTTPS-хост за один 301.
HTTP с www сохраняет два перехода; проверенный CSS-файл на HTTPS
с www отдаётся с кодом 200 без удаления www. Все конечные ответы
имеют ожидаемые статусы, путь и параметры сохраняются, ошибок TLS нет.
Ограничение внешнего сервера остаётся; пункт полностью не закрыт.
Подробный протокол: redirects-after-htaccess-check.json.

Если после вставки появился HTTP 500, восстановите резервную копию
.htaccess и прежнее значение «Редирект домена». Для отката только этого
блока можно удалить строки от # BEGIN CookLook www redirect
до # END CookLook www redirect включительно.
